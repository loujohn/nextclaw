# v0.15.53-employee-chat-initial-session-request-cancel-fix

## 迭代完成说明

修复了数字员工聊天页首次进入会话列表时，首条会话详情接口被立即取消的问题。

本次根因在于初始化流程同时存在两条详情加载路径：
- `initializeChat()` 在选中首条会话后会直接调用一次详情加载
- `activeSessionKey` 的 `watch` 在同一轮状态变更后也会再次触发详情加载

第二条路径进入时会先执行 `invalidateMessageLoad()`，从而中止第一条尚未完成的请求，表现为首条会话详情接口在初始进入时被取消。

本次修复将“首次初始化后是否应由 watcher 接管详情加载”收敛为单一决策，确保：
- 首次从空选中切到首条会话时，仅由 watcher 触发一次详情加载
- 若初始化后选中会话未变化，则仍允许当前流程直接刷新详情

## 用户/产品视角的验收步骤

1. 打开任一已有聊天历史的数字员工详情页聊天标签。
2. 首次进入页面时观察网络请求，确认首条会话详情接口只发起一次，状态为成功而非 cancelled。
3. 确认右侧消息区正常展示首条会话历史消息，而不是短暂加载后被清空或重新闪动。
4. 刷新页面后重复验证一次，确认行为稳定。
5. 切换到其他会话，再返回首条会话，确认详情仍能正常加载。
