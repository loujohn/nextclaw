# v0.15.4-digital-employee-chat-upload-files-design

## 迭代完成说明

本次迭代新增了数字员工聊天模块“对话文件上传功能”的详细架构与技术方案文档，覆盖以下内容：

1. 聊天输入区多文件上传、发送前删除、消息附件展示方案。
2. 文件存储到员工工作空间 `uploadFile/YYYY-MM-DD` 的目录设计，以及“唯一前缀 + 原始文件名”的落盘规则。
3. 实时对话页、历史记录页与工作空间页之间的附件精确关联模型。
4. 工作空间“核心文件 / 上传文件”可展开收起结构与默认选中规则。
5. 发送文字与文件存储路径给智能体的上下文拼装策略。
6. 首期采用“方案 B：工作空间物理文件 + 消息附件快照”的落地架构。

详细设计文档见：

- [数字员工聊天模块新增对话文件上传能力设计文档](../../superpowers/specs/2026-04-14-digital-employee-chat-upload-files-design.md)

## 测试/验证/验收方式

本次为设计文档迭代，验收以文档完整性与可落地性为主：

1. 确认文档明确了前端、后端、数据模型、接口、工作空间交互与验收标准。
2. 确认文档反映已确定的产品边界：
   - 文档优先上传范围
   - 发送前可删除、发送后不可删除
   - 采用方案 B
3. 确认工作空间路径、会话关联、默认选中规则与来源信息展示均有说明，且不会因文件重名串数据。
4. 确认文档中包含后续实施拆分，便于按阶段开发。

## 发布/部署方式

本次迭代仅新增方案文档，不涉及构建产物发布或部署。

后续若进入开发落地，建议按文档中的实施拆分逐步上线：

1. 先上线上传服务与消息 metadata。
2. 再上线聊天页附件交互与历史回显。
3. 最后上线工作空间上传文件树与统一预览面板。

## 用户/产品视角的验收步骤

1. 打开方案文档，确认聊天页、历史页、工作空间页的行为描述与产品预期一致。
2. 确认员工工作空间中的上传目录为 `uploadFile/YYYY-MM-DD`。
3. 确认从“工作空间”tab 进入默认选中核心文件第一个文件。
4. 确认从会话中的上传文件进入工作空间时默认选中被点击的文件，且展示样式与普通进入一致。
5. 确认工作空间页面会展示上传文件的来源会话、来源消息与随文件发送的文字信息。
